# assets/fonts：自托管的网页字体

四个新主题（夜航、笺、唱片、绕日）用到的全部字体都在这个目录里，和网站同源，不向任何第三方请求。旧版主题不用这里的东西。

打开 [`specimen.html`](specimen.html)（本地是 `http://localhost:4301/assets/fonts/specimen.html`）可以看到每个字族、每个字重的样子，页面底部会报告有没有字漏到系统字体上。

## 这里有什么

| 文件 | CSS 里的名字 | 来自 | 字重 | 用在 |
|---|---|---|---|---|
| `serif-sc.css` + `serif-sc/` | `"F221 Serif"` | 思源宋体 Noto Serif SC | 300–700，连续可变 | 夜航、绕日 |
| `sans-sc.css` + `sans-sc/` | `"F221 Sans"` | 思源黑体 Noto Sans SC | 400–900，连续可变 | 唱片 |
| `sans-sc-400.css`（文件也在 `sans-sc/`） | `"F221 Sans 400"` | 同上 | 只有 400，体积减半 | 夜航里的小标签 |
| `fangsong.css` + `fangsong/` | `"F221 Fangsong"` | 朱雀仿宋 | 400 | 笺 |
| `mono.css` + `mono/` | `"F221 Mono"` | IBM Plex Mono | 300、400、500 | 夜航的日期与数字 |
| `garamond.css` + `garamond/` | `"F221 Garamond"` | EB Garamond | 400 正体与斜体 | 笺的西文与数字 |
| `grotesk.css` + `grotesk/` | `"F221 Grotesk"` | Archivo | 400–900，宽度 62–100% | 唱片的西文与数字 |
| `text.css` + `text/` | `"F221 Text"` | Source Serif 4 | 300–700 正体，400 斜体 | 绕日的西文与数字 |

另外还有：`LICENSES.md` 与 `OFL.txt`（许可）、`manifest.json`（每个文件的大小与字数，脚本写的）、`specimen.html`（样张）。

名字都是 F221 开头，不是原字体的名字。原因：这些文件是原字体的子集，按 OFL 许可算"修改版"，而其中几款字体保留了自己的名字不许修改版使用，所以统一改名。详见 `LICENSES.md`。

每个 CSS 文件里只有 `@font-face` 规则，全部是 `font-display: swap`：文字先用系统字体显示，字体到了再换上。主题用哪些字族，写在 `_data/themes.yml` 里，页面只加载那几个 CSS。

## 中文字体为什么切成很多小文件

一款中文字体有几万个字，整个下载要十几 MB。这里把每款中文字体按 `unicode-range` 切成两百来个小文件（"切片"），CSS 告诉浏览器每个文件里有哪些字，浏览器看页面上实际出现了哪些字，只下载用得到的那几片。

| 切片 | 里面是什么 | 什么时候会被下载 |
|---|---|---|
| `a` | 首页会出现的字：所有信的标题、地点、作者、歌名与歌手、界面上的字、英文字母、数字、标点、列表的圆点，再加上信里最常用的 200 个字 | 打开任何一页 |
| `q` | 每封信的题记（front matter 里的 `quote`）里、`a` 没有的字 | 页面上出现题记时 |
| `b01`–`b03` | 信的正文里、至少两封信都用到的字，越常见的越靠前 | 读第一封信时，之后不用再下 |
| `l01`–`l31` | 只有一封信用到的字，一封信一片：`l07` 就是第 7 封信（最早的是第 1 封） | 读到那封信时（3–37 KB） |
| `s1`–`s4` | 还没人用过的：带声调的拉丁字母与希腊字母、符号、中文符号与全角字符、假名 | 用到才下 |
| `c001`–`c131` | 《通用规范汉字表》一级、二级字（共 6500 个常用字）里，上面没包括的那些，按常用程度排列，每片几个到六十几个字 | 用到才下 |
| `t01`–`t35` | 常见的繁体字和粤语用字（信里引过粤语歌词） | 用到才下 |

`a`、`q`、所有 `b` 和 `l` 切片带全部字重；其余切片只有常规体一种粗细。

`c`、`t` 切片故意切得很小，而且每个字在哪一片是固定的（由它在 `scripts/fonts-data/hanzi.txt` 里的位置决定，和别的字无关）。好处有两个：新信里出现新字时，读者只需多下十来个几 KB 的小文件；重新生成字体时，`c`、`t` 里只有新字原来所在的那几片会变，其余的一个字节都不动。

实测（把四个主题的样稿换上这里的字体，在 Chrome 和 WebKit 里把 31 封信逐封打开，记录浏览器真正下载了什么）：

| 主题 | 打开首页 | 再读第一封信 | 之后每多读一封 |
|---|---|---|---|
| 夜航 | 328 KB，4 个文件 | 再加 385–506 KB | 3–73 KB |
| 笺 | 243 KB，3 个文件 | 再加 322–354 KB | 3–35 KB |
| 唱片 | 231 KB，2 个文件 | 再加 293–318 KB | 0–29 KB |
| 绕日 | 300 KB，3 个文件 | 再加 376–410 KB | 0–37 KB |

每个中文字族的 CSS 本身约 87 KB（gzip 后约 23 KB），夜航用两个中文字族，所以是两份。整个目录 9.9 MB、六百多个文件，其中约 6 MB 是为以后的新字预备的 `c`、`t` 切片，平时没有人会下载它们。

## 新写一封信，用了以前没用过的字，会怎样

**什么都不用做，字不会掉成系统字体。** 6500 个常用字和一千多个繁体字都已经在 `c`、`t` 切片里了，浏览器遇到新字会自己去取对应的那一片。

代价只是读者读这封新信时要多下载一些小文件。按现有的 31 封信估算（把每一封都当作"新写的"算一遍），一封新信通常带来 18 个左右的新字，差不多每个字落在不同的切片里，也就是十五六个小文件：宋体一共约多下 120 KB，黑体约 100 KB，仿宋约 200 KB。新字特别多的长信（七十多个新字）会到 400–900 KB。新标题里的字如果不在 `a` 里，首页也会多下一两个小文件。

想把这点代价也省掉，就重新生成一次字体（见下一节）：新字会被挪进这封信自己的 `l` 切片，新标题会被挪进 `a`。这一步随时可以做，不做也不影响网站。

两种情况要留意：

- **标题或加粗的文字里有新字**：在重新生成之前，这个字是常规粗细，旁边的字是粗的。重新生成后恢复正常。
- **用了 6500 常用字之外的生僻字**（多见于人名，例如"喆"）：切片里没有，这个字会由系统字体显示。重新生成一次就好，脚本会把信里出现的任何字都收进去，只要原字体里有。

不确定的话，运行检查（不需要装任何东西）：

```
python3 scripts/fonts.py --check
```

它会列出：哪些字不在首屏切片里、哪些字落在了后面的切片里、有没有字完全没被覆盖。最后一行是 `check: ok` 就没有问题。

## 怎么重新生成

生成工具是 `scripts/fonts.py`，文件开头有完整说明。它**不属于网站构建，CI 里也不跑**；生成出来的 WOFF2 和 CSS 是直接提交进仓库的。原始字体文件不进仓库。

```
python3 scripts/fonts.py --fetch   # 下载原始字体到 .fonts-src/（54 MB，核对 SHA-256）；不需要装任何东西
npm run images                     # 如果 _data/media.json 还不存在（歌名、歌手从这里来）
uv run scripts/fonts.py            # 重新生成 assets/fonts/，一分钟左右
git add -A assets/fonts && git commit
```

生成需要 fontTools 和 brotli 两个 Python 包。[uv](https://docs.astral.sh/uv/) 会按脚本开头写的版本自己装到一个临时环境里，用完即弃，不会动系统的 Python。不想用 uv 的话，自己建一个虚拟环境也一样：

```
python3 -m venv .venv-fonts        # Debian / Ubuntu 上要先装 python3-venv，否则这一步会报错
.venv-fonts/bin/pip install fonttools==4.65.0 brotli==1.2.1
.venv-fonts/bin/python scripts/fonts.py
```

`.fonts-src/` 和 `.venv-fonts/` 已经在 `.gitignore` 里。同样的输入每次生成出完全相同的文件，没有变化的切片不会出现在 `git status` 里。加了一封新信之后重新生成，会变的是：`a`、`q`、`b01`–`b03`、新信自己的 `l` 切片、几片因为有字被新信"借走"而变小的 `l` 和 `c` 切片，一共几十个文件、每个字族 0.6–1.7 MB；其余一百多个文件不动。

脚本从这些地方收集"首页会出现的字"：`_posts/` 里每封信的 `title`、`author`、`place`、`bgm`、`quote`，`_data/media.json` 里的歌名与歌手，`scripts/fonts-data/ui.txt`（界面用字，可以手工往里加），以及 `assets/themes/`、`assets/js/core/`、`_includes/`、`_layouts/`、`_data/themes.yml` 里出现的非英文字符。所以**改了主题界面上的文字之后，也值得重新生成一次**，否则那几个字可能落在 `b` 切片里，首页就要多下载 60–330 KB。

常用字表与繁体字表在 `scripts/fonts-data/hanzi.txt`，来源写在文件开头。**不要给这两张表重新排序**，也不要在中间插字（要加字就加在末尾）：`c`、`t` 切片是按表里的位置切的，顺序一变，后面所有切片都会改名重写。

## 给写主题的人

- 字体栈：**西文字族在前，中文字族在后，最后是系统字体**。例如

  ```css
  font-family: "F221 Text", "F221 Serif", "Songti SC", "Noto Serif CJK SC", serif;       /* 绕日 */
  font-family: "F221 Grotesk", "F221 Sans", "PingFang SC", "Microsoft YaHei", sans-serif; /* 唱片 */
  ```

  西文字族的 `unicode-range` 故意不包含 `·` `—` `‘’` `“”` `…`，所以中文里的引号、破折号、省略号、间隔号永远由中文字体来画（宽度、位置、竖排字形才对）。
- 整段英文（英文歌词）标上 `lang="en"`，并换用带 `En` 的同名字族，例如 `"F221 Garamond En"`、`"F221 Text En"`：同一个文件，但引号和撇号归西文字体，`don’t` 才不会被撑开。不多占流量。
- 写上 `font-synthesis: none`。中文字体没有斜体；`F221 Fangsong`、`F221 Sans 400` 没有粗体。不写这一句，浏览器会自己"造"出歪的、糊的字。
- 竖排用 `F221 Fangsong`。逗号句号、破折号、省略号、括号、书名号都会自动换成竖排字形。弯引号 `“”` 在 Chrome 里会变成 `『』`；在 Safari 里，仿宋会变，宋体和黑体不变，所以竖排的文字最好直接写直角引号 `「」『』`。
- `F221 Serif` 与 `F221 Sans` 的破折号已经固定成中文的样子（占满一个字宽、两个连写不断开），不依赖页面的 `lang`。
- 不要为了几个字多引入一个中文字族：每多一个中文字族，首页多 90–220 KB，CSS 多 23 KB（gzip）。
- 信里有两处 `<code>` 夹着中文（第 12、19 封）。给 `code` 单独指定等宽字体时，字体栈末尾要接上主题自己的中文字族，例如 `ui-monospace, Menlo, Consolas, "F221 Serif", monospace`，否则这几个中文字会由系统字体来画。
- 列表的圆点、着重号（`text-emphasis`）这类浏览器自己画的符号已经放进 `a` 切片，不会为了一个圆点多下载文件。朱雀仿宋没有空心圆点、实心圆和芝麻点（`◦ ● ○ ﹅ ﹆`），笺里的着重号请用 `dot`（`•`）。
